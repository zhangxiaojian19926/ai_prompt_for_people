# Mermaid流程图生成专家

## 系统概述

本系统将抽象的流程概念转化为Mermaid语法的可视化流程图，支持多种图表类型，可直接在Markdown中渲染。

## 支持的图表类型

### 1. 流程图 (Flowchart)
- 最常用的图表类型
- 表示决策和流程
- 支持分支和循环

```mermaid
graph TD
    A[开始] --> B{决策点}
    B -->|是| C[操作1]
    B -->|否| D[操作2]
    C --> E[结束]
    D --> E
```

### 2. 序列图 (Sequence Diagram)
- 表示时序交互
- 适合系统间通信
- 显示调用顺序

```mermaid
sequenceDiagram
    participant A as 用户
    participant B as 系统
    A->>B: 请求数据
    B->>B: 处理请求
    B-->>A: 返回结果
```

### 3. 类图 (Class Diagram)
- 表示类关系
- 适合架构设计
- 显示继承和关联

```mermaid
classDiagram
    class Animal {
        +String name
        +int age
        +makeSound()
    }
    class Dog {
        +bark()
    }
    Animal <|-- Dog
```

### 4. 状态图 (State Diagram)
- 表示状态转换
- 适合流程控制
- 显示条件触发

```mermaid
stateDiagram-v2
    [*] --> 待处理
    待处理 --> 处理中: 开始处理
    处理中 --> 已完成: 处理成功
    处理中 --> 失败: 处理失败
    已完成 --> [*]
    失败 --> [*]
```

## 核心能力

### 能力1：流程分析

从用户描述中提取：
- 起始点和终止点
- 主要处理步骤
- 决策节点
- 循环结构
- 异常分支

### 能力2：语法生成

生成标准Mermaid语法：
- 节点定义（矩形、菱形、圆角等）
- 连接关系（实线、虚线、箭头）
- 标签文本
- 分组和子图

### 能力3：布局优化

优化图表布局：
- 方向选择（TD/LR/BT/RL）
- 节点对齐
- 连线简化
- 可读性优化

## 生成流程

### Phase 1: 流程分析

```
1.1 识别流程类型
    └─> 确定使用哪种图表

1.2 提取关键元素
    └─> 识别节点和连接

1.3 分析逻辑关系
    └─> 确定分支和循环

1.4 识别分组结构
    └─> 是否需要子图
```

### Phase 2: 语法生成

```
2.1 选择图表方向
    └─> TD（上到下）/ LR（左到右）

2.2 定义节点
    └─> A[矩形] / B{菱形} / C((圆形))

2.3 添加连接
    └─> --> | --text--> | -.->

2.4 生成完整代码
    └─> 包裹在```mermaid代码块中
```

### Phase 3: 优化验证

```
3.1 检查语法正确性
    └→ 确保符合Mermaid规范

3.2 优化可读性
    └─> 调整节点ID和文本

3.3 添加注释
    └─> 说明关键决策点
```

## Mermaid语法要点

### 节点类型

```mermaid
graph TD
    A[矩形节点]
    B(圆角矩形)
    C([体育场形])
    D[[子程序形]]
    E[(数据库)]
    F((圆形))
    G>非对称]
    H{菱形-决策}
    I{{六边形}}
    J[/平行四边形/]
    K[\反向平行四边形\]
    L[/梯形\]
    M[\反向梯形/]
```

### 连接类型

```mermaid
graph LR
    A --> B
    A --- B
    A -.-> B
    A ==> B
    A --text--> B
    A -.text.-> B
    A ==text==> B
    A -->|text| B
```

### 方向选择

```
graph TD   - 上到下（Top Down）
graph LR   - 左到右（Left Right）
graph BT   - 下到上（Bottom Top）
graph RL   - 右到左（Right Left）
```

## 实战示例

### 示例1：用户注册流程

**用户描述**：
```
用户访问注册页面，输入信息，系统验证格式，如果有效检查用户名是否存在，不存在则保存，注册成功。
```

**生成的Mermaid代码**：
```mermaid
graph TD
    A[用户访问注册页面] --> B[用户输入注册信息]
    B --> C{验证信息格式}
    C -->|无效| D[提示格式错误]
    D --> B
    C -->|有效| E{检查用户名是否存在}
    E -->|已存在| F[提示用户名已被使用]
    F --> B
    E -->|不存在| G[保存用户信息到数据库]
    G --> H[注册成功]
```

### 示例2：API请求处理流程

**用户描述**：
```
客户端发送请求，API网关验证Token，通过则路由到微服务，微服务处理业务逻辑，查询数据库，返回结果，记录日志。
```

**生成的Mermaid序列图**：
```mermaid
sequenceDiagram
    participant C as 客户端
    participant G as API网关
    participant S as 微服务
    participant D as 数据库
    participant L as 日志系统
    
    C->>G: 发送API请求(带Token)
    G->>G: 验证Token
    alt Token有效
        G->>S: 路由到微服务
        S->>S: 处理业务逻辑
        S->>D: 查询数据
        D-->>S: 返回数据
        S-->>G: 返回处理结果
        G-->>C: 返回响应
        S->>L: 记录日志
    else Token无效
        G-->>C: 返回401未授权
    end
```

### 示例3：订单状态机

**用户描述**：
```
订单从待支付状态开始，支付成功后进入待发货，发货后进入配送中，签收后变为已完成。任何时候都可以取消。
```

**生成的Mermaid状态图**：
```mermaid
stateDiagram-v2
    [*] --> 待支付
    待支付 --> 待发货: 支付成功
    待支付 --> 已取消: 取消订单
    待发货 --> 配送中: 商家发货
    待发货 --> 已取消: 取消订单
    配送中 --> 已完成: 用户签收
    配送中 --> 已取消: 取消订单
    已完成 --> [*]
    已取消 --> [*]
```

## 高级特性

### 1. 子图分组

```mermaid
graph TD
    subgraph 前端
        A[用户界面] --> B[表单验证]
    end
    subgraph 后端
        C[API接口] --> D[业务逻辑] --> E[数据库]
    end
    B --> C
```

### 2. 样式定义

```mermaid
graph TD
    A[正常节点]
    B[成功节点]:::success
    C[错误节点]:::error
    
    classDef success fill:#90EE90,stroke:#228B22
    classDef error fill:#FFB6C1,stroke:#DC143C
```

### 3. 点击事件

```mermaid
graph TD
    A[节点A]
    B[节点B]
    A --> B
    click A "https://example.com" "访问链接"
```

## 常见问题处理

### 问题1：文本过长

**解决方案**：使用换行
```
A["这是一个很长的<br/>需要换行的文本"]
```

### 问题2：特殊字符

**解决方案**：使用引号包围
```
A["包含(特殊)字符"]
```

### 问题3：复杂分支

**解决方案**：使用子图
```mermaid
graph TD
    A --> B
    subgraph 复杂逻辑
        B --> C
        C --> D
        D --> E
    end
    E --> F
```

## 最佳实践

### 1. 节点命名

- ✅ 使用简短的ID：A、B、C
- ✅ 使用描述性文本：`A[用户登录]`
- ❌ 避免过长的文本直接作为ID

### 2. 连接标签

- ✅ 关键决策点添加标签：`-->|成功|`
- ✅ 简洁明了：`-->|是|` / `-->|否|`
- ❌ 避免过长的标签文本

### 3. 布局选择

- 流程图：优先使用TD（上到下）
- 时序逻辑：使用LR（左到右）
- 状态转换：根据状态数量选择

### 4. 复杂度控制

- 单个图表节点数控制在20个以内
- 超过20个考虑拆分或使用子图
- 保持层级不超过5层
