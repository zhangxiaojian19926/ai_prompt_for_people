# 提示词质量评估工作流

## 系统概述

本系统提供完整的提示词生成→评估→优化循环，确保输出的提示词达到工业级质量标准。

## LLM辅助的提示词生成与评估工作流

### 完整流程图

```
用户需求
    ↓
[阶段一：提示词生成]
    ├─→ 理解需求
    ├─→ 设计初稿
    └─→ 生成提示词 v1.0
          ↓
[阶段二：提示词评估]
    ├─→ 多维度评分
    ├─→ 问题识别
    └─→ 改进建议
          ↓
    是否达标？
    ├─→ 是：交付使用
    └─→ 否：返回优化 → 生成 v1.1
```

## 阶段一：提示词生成 (Prompt Generation)

### 生成流程

```
Step 1: 需求分析
    └─→ 理解用户意图和使用场景

Step 2: 框架选择
    └─→ PARE / Role / 自定义

Step 3: 结构设计
    └─→ 定义模块和层级

Step 4: 内容填充
    └─→ 编写具体内容

Step 5: 初稿生成
    └─→ 输出 v1.0 版本
```

### 生成标准

- ✅ 包含完整的必需模块
- ✅ 角色定义清晰
- ✅ 任务指令明确
- ✅ 约束条件完整
- ✅ 输出格式规范
- ✅ 提供示例说明

## 阶段二：提示词评估 (Prompt Evaluation)

### 评估维度（8个维度，100分制）

#### 1. 清晰度 (Clarity) - 15分

**评分标准：**
- 优秀 (13-15分)：意图明确，无歧义，每个要求都清晰具体
- 良好 (10-12分)：基本清晰，少量模糊表达
- 及格 (7-9分)：部分清晰，存在歧义
- 不及格 (<7分)：模糊不清，难以理解

**检查点：**
- [ ] 是否消除了所有模糊词汇？（如"适当"、"一些"）
- [ ] 是否量化了具体要求？（如字数、数量）
- [ ] 是否明确了每个术语的含义？

#### 2. 完整性 (Completeness) - 15分

**评分标准：**
- 优秀 (13-15分)：包含所有必需模块，无遗漏
- 良好 (10-12分)：主要模块完整，次要部分可能缺失
- 及格 (7-9分)：缺少关键模块
- 不及格 (<7分)：严重不完整

**检查点：**
- [ ] 是否包含角色定义？
- [ ] 是否包含任务说明？
- [ ] 是否包含约束条件？
- [ ] 是否包含输出格式？
- [ ] 是否包含质量标准？
- [ ] 是否包含示例？

#### 3. 结构化 (Structure) - 10分

**评分标准：**
- 优秀 (9-10分)：层级清晰，逻辑严密，易于导航
- 良好 (7-8分)：基本结构合理
- 及格 (5-6分)：结构混乱
- 不及格 (<5分)：无明显结构

**检查点：**
- [ ] 是否使用了标题层级？
- [ ] 是否使用了列表和编号？
- [ ] 是否模块化组织？

#### 4. 可执行性 (Actionability) - 15分

**评分标准：**
- 优秀 (13-15分)：每个指令都可直接执行
- 良好 (10-12分)：大部分可执行
- 及格 (7-9分)：部分可执行
- 不及格 (<7分)：难以执行

**检查点：**
- [ ] 指令是否具体？
- [ ] 是否有明确的步骤？
- [ ] 是否定义了判断标准？

#### 5. 专业度 (Professionalism) - 10分

**评分标准：**
- 优秀 (9-10分)：术语准确，表达规范，权威性强
- 良好 (7-8分)：基本专业
- 及格 (5-6分)：口语化较重
- 不及格 (<5分)：不专业

**检查点：**
- [ ] 是否使用标准术语？
- [ ] 是否避免口语化？
- [ ] 是否保持一致性？

#### 6. 示例质量 (Example Quality) - 10分

**评分标准：**
- 优秀 (9-10分)：提供多个高质量示例，覆盖典型和边界情况
- 良好 (7-8分)：有示例但不全面
- 及格 (5-6分)：示例简单或不当
- 不及格 (<5分)：无示例或错误示例

**检查点：**
- [ ] 是否提供了示例？
- [ ] 示例是否具体？
- [ ] 是否包含边界情况？

#### 7. 约束合理性 (Constraint Validity) - 10分

**评分标准：**
- 优秀 (9-10分)：约束明确且合理，平衡了自由度和控制
- 良好 (7-8分)：约束基本合理
- 及格 (5-6分)：约束过松或过严
- 不及格 (<5分)：约束不合理或缺失

**检查点：**
- [ ] 是否定义了"必须"和"禁止"？
- [ ] 约束是否可验证？
- [ ] 是否平衡了灵活性？

#### 8. 模型适应性 (Model Compatibility) - 15分

**评分标准：**
- 优秀 (13-15分)：完全符合LLM理解习惯，易于执行
- 良好 (10-12分)：基本适配
- 及格 (7-9分)：部分不适配
- 不及格 (<7分)：难以被模型理解

**检查点：**
- [ ] 是否有明确的角色定义？
- [ ] 指令格式是否标准？
- [ ] 是否避免了过于复杂的嵌套？

## 迭代优化循环

### 优化流程

```
v1.0（初始版本）
    ↓
评估（60分）
    ↓
识别问题，提出改进建议
    ↓
v1.1（改进版本）
    ↓
评估（75分）
    ↓
继续优化
    ↓
v1.2（优化版本）
    ↓
评估（90分）
    ↓
达标，正式发布
```

### 迭代示例

**v1.0 版本（60分）**：
```
帮我写一篇关于AI的文章
```
问题：太简单，缺少所有关键要素

**v1.1 版本（75分）**：
```
你是一位科技作者。请写一篇1500字的AI科普文章，包含基本概念、应用案例和未来展望。使用Markdown格式输出。
```
改进：添加了角色、字数、内容要求、格式
问题：缺少风格定义、示例、约束

**v1.2 版本（90分）**：
```markdown
# 角色
你是一位资深科技作者，擅长撰写面向普通读者的技术科普文章。

# 任务
撰写一篇1500-2000字的AI技术科普文章。

# 目标受众
对AI感兴趣但无技术背景的普通读者

# 内容要求
## 必须包含
1. 吸引人的标题
2. AI基本概念（300字）
3. 实际应用案例（500字，至少3个）
4. 对生活的影响（400字）
5. 未来展望（300字）

## 写作风格
- 通俗易懂，避免专业术语
- 真实案例，贴近生活
- 客观中立，适度乐观

# 输出格式
[Markdown模板]

# 质量标准
- 准确性：技术信息准确
- 可读性：初中生能看懂
- 吸引力：开篇吸引注意
```
达标：完整、清晰、可执行
