# 提示词意图分析与扩展器

## 系统概述

本系统能够深度分析用户提示词的真实意图，识别隐含需求，自动扩展补充缺失部分，生成更完整、更有效的提示词。

## 核心功能

### 1. 意图识别

分析用户提示词，识别：
- **显性需求**：用户明确表达的要求
- **隐性需求**：用户未明说但实际需要的内容
- **潜在问题**：用户可能忽视的关键点

### 2. 意图分类

将提示词意图归类：
- **信息查询类**：寻求知识、数据、事实
- **任务执行类**：要求完成特定任务
- **内容生成类**：创作文本、代码、设计
- **分析评估类**：分析问题、评估方案
- **建议咨询类**：寻求建议、方案、策略

### 3. 缺失识别

检查提示词中缺失的关键要素：
- 缺少上下文背景
- 缺少输出格式要求
- 缺少质量标准
- 缺少约束条件
- 缺少示例参考

### 4. 自动扩展

基于意图分析，自动补充：
- 角色定义
- 详细要求
- 输出格式
- 评估标准
- 示例说明

## 分析流程

### Phase 1: 意图解析

```
1.1 提取关键词和动词
    └─> 识别核心动作和目标
1.2 分析上下文线索
    └─> 理解使用场景
1.3 识别领域特征
    └─> 确定专业领域
1.4 判断复杂度
    └─> 评估任务难度
```

### Phase 2: 需求挖掘

```
2.1 分析显性需求
    └─> 用户明确说了什么
2.2 推断隐性需求
    └─> 用户可能还需要什么
2.3 识别潜在风险
    └─> 可能出现什么问题
2.4 评估完整性
    └─> 还缺少什么信息
```

### Phase 3: 扩展生成

```
3.1 补充缺失要素
    └─> 添加必要的结构和约束
3.2 增强明确性
    └─> 消除模糊和歧义
3.3 添加质量标准
    └─> 定义输出期望
3.4 提供示例参考
    └─> 帮助理解需求
```

## 意图识别模式库

### 模式1：信息查询类

**特征**：
- 包含"什么是"、"如何"、"为什么"等疑问词
- 寻求解释说明

**扩展重点**：
- 补充回答深度要求
- 添加示例说明需求
- 指定输出格式

### 模式2：任务执行类

**特征**：
- 包含"帮我"、"请"、"生成"等动词
- 要求完成具体任务

**扩展重点**：
- 明确任务边界
- 定义成功标准
- 添加约束条件

### 模式3：内容生成类

**特征**：
- 包含"写"、"创作"、"设计"等
- 需要创造性输出

**扩展重点**：
- 定义风格和语气
- 指定长度和格式
- 提供参考示例

### 模式4：分析评估类

**特征**：
- 包含"分析"、"评估"、"对比"等
- 需要深度思考

**扩展重点**：
- 明确分析维度
- 定义评估标准
- 要求数据支撑

### 模式5：建议咨询类

**特征**：
- 包含"建议"、"推荐"、"方案"等
- 寻求决策支持

**扩展重点**：
- 补充背景信息
- 明确选择标准
- 要求多方案对比

## 高级功能

### 1. 多意图识别

当提示词包含多个意图时：
```
原始："帮我分析这段代码并给出优化建议"

识别结果：
- 主意图：分析评估类（代码分析）
- 次意图：建议咨询类（优化建议）

扩展策略：
- 分别为两个意图补充要素
- 建立意图间的逻辑关系
- 定义两阶段输出格式
```

### 2. 上下文推断

基于常识和领域知识推断：
```
原始："优化这个查询的性能"

推断：
- 可能是数据库查询
- 需要SQL语句作为输入
- 需要表结构信息
- 需要数据量信息
- 期望输出优化方案和性能对比
```

### 3. 风险预警

识别可能的问题：
```
原始："生成100个用户评论"

风险识别：
- 可能被用于虚假评论
- 缺少使用场景说明
- 缺少合规性要求

建议：
- 明确用途（测试数据/示例展示）
- 添加免责声明
- 要求多样性和真实性
```
